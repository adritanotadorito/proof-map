# Lessons log

Decisions and failure modes observed while building ProofMap. Each one says where it was seen. Unless an entry says production, it happened during local development.

| # | Observed | Lesson | Design decision |
| --- | --- | --- | --- |
| 1 | Gemini rejected the response schema with HTTP 400 when it contained `minItems` / `maxItems` (local). | The model API supports only part of JSON Schema. | `modelJsonSchema()` strips array and string bounds before sending. zod enforces the full shape, bounds included, on the response. If a strict request is still rejected with 400, the call is retried once in plain JSON mode. |
| 2 | Design risk, not a production incident: a response can pass schema checks and still cite a path, range or quote that is not in the pinned code. | A citation is a claim too and needs its own check. | Every citation is checked against the pinned snapshot: the file exists at the head SHA, the range is valid and at most 150 lines, the quote appears in those lines, and diff citations touch changed lines. Any failure marks the statement unsupported. |
| 3 | "Citation confirmed" was easy to read as "verified". | Location is not correctness. | Separate labels: *cited* for found citations, *verified* reserved for an executed check, which does not exist yet. Build, test and fault probe always show "Not run". |
| 4 | The model writes sentences about tests passing even though nothing ran. Seen again in production on #2283 ("Run the new unit tests… to confirm…"). | Models describe outcomes they have not observed. | Sentences that mention test or build outcomes are listed as "intent, not results" under the review. |
| 5 | A review request hung with no error and no feedback (local). | Unbounded model calls leave the reviewer guessing. | 2-minute timeout, at most two attempts (one corrective retry for malformed output), and a stored failure record shown on the page. |
| 6 | Page loads were slow because GitHub lookups ran one after another (local). | Latency was in the waterfall, not in GitHub itself. | Independent lookups run in parallel. Responses addressed by full commit SHA are cached in memory, since they cannot change. All change tabs render once and switch on the client without a server round trip. |
| 7 | A temporary anonymous GitHub read path used for local testing hit GitHub's unauthenticated rate limit. | Shortcuts around auth create their own failures and are a security risk. | The anonymous path and test session were removed. All GitHub calls use the signed-in user's GitHub App token, and no bypass route exists. |
| 8 | Review and decision records were JSON files in `.data/`. Vercel's filesystem is read-only and does not persist. Found during the pre-deployment check, before any production data was written. | Local files are fine for development, wrong for serverless. | Upstash Redis over its REST API (no new dependency) when `KV_REST_API_URL` / `KV_REST_API_TOKEN` are set. Decisions are appended, never overwritten. On Vercel without a store, writes raise an error instead of being lost. Verified in production: a review and a Defer decision persisted across reloads. |
| 9 | The landing reference design showed sample activity numbers. | Demo data in a trust product is a false claim. | The activity heatmap counts only the signed-in user's recorded reviews and decisions; the empty state says so. |
| 10 | The callback URL defaulted to `localhost`. | Deploy-time configuration must not depend on code edits. | `APP_URL` sets the base URL, falling back to Vercel's production domain, and to localhost only in development. |
